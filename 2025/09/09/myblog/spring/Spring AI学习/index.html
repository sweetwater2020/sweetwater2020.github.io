第一章 新建项目

新建项目，划分模块：common、model、repository、service、start.

pom中：modules、properties、dependencies、dependencyManagement、build。

dependencyManagement 用于版本控制，dependencies 用于实际的依赖引入。这两者多模块项目中结合使用，dependencyManagement 在父模块中被用作标准的依赖版本管理工具，而 dependencies 在子模块中负责添加具体的依赖到项目中。

大模型流式输出：通过Reactor框架来实现，它是一个响应式编程库，提供构建异步和非阻塞应用程序的能力。

OpenAI的API规范，其他厂商也兼容。类似JDBC驱动可以连接不同数据库，Spring AI的客户端也能适配不同AI服务。

监控：

添加依赖：spring-boot-starter-actuator、micrometer-registry-prometheus（用于将 Spring Boot 应用的性能指标暴露给 Prometheus）

启动监控： management.endpoints.web.exposure.include=health,metrics,prometheus（用于暴露 Spring Boot Actuator 的管理端点） spring.ai.observability.enabled=true（用于启用 Spring AI 的可观测性功能，收集与 AI 相关的性能指标、日志和追踪信息）

访问/actuator/prometheus

第二章 提示词

三种提示词：Prompt、PromptTemplate中用{}作为占位符，调用render做占位符填充构建、Message做角色扮演，提前约定大模型的功能角色，SystemMessage系统消息设定对话的背景、规则和指令，UserMessage表示用户输入，AssistantMessage表示AI的回复，ToolResponseMessage表示AI调用外部工具后返回工具的执行结果。

好的提示词：样例法则、分布法则、分隔法则、引导法则。

提示词管理：统一放在prompts文件夹里，用@Value(“classpath:/prompts/xx”) Resource.

第三章 结构化输出转换器

大模型输出纯文本，需要额外解析正则才能被程序使用，容易出错。Spring AI通过在提示词中添加格式化指令要求大模型按特定格式做内容返回，在拿到大模型输出数据后通过内置转换器的能力做结构化输出。

BeanOutputConverter beanOutputConverter = new BeanOutputConverter<>(new ParameterizedTypeReference() { });

通过BeanOutputConverter 的泛型约定返回结果的实体对象

在提示词后面追加{format}占位符，该占位符对应的值为beanOutputConverter.getFormat()

调用beanOutputConverter.convert(content)处理大模型返回数据，得到返回实体。

ParameterizedTypeReference 是 Spring 框架中的一个类，用来保存泛型类型的信息。在 Java 中，由于类型擦除的存在，在运行时通常无法获取泛型类型的信息。例如，List 和 List 在运行时都被擦除为 List，无法区分两者。但有时我们需要区分泛型类型，于是 ParameterizedTypeReference 提供了这种能力。通过匿名类实例创建泛型类型引用，使得在运行时仍然可以获取Film的具体类型。

优雅的entity()写法：直接在call后面调用entity，把对应的class类型传递进去即可，提示词中也不需要加format。

.call().entity(Film.class);

列表输出：ListOutputConverter

Map输出：MapOutputConverter

第四章 本地模型部署

用Ollama（一个开源的本地大语言模型运行工具）在本地部署大模型。使用ollama pull llama3.1:8b 进行模型的下载。

ollama list查看本地的模型列表

ollama run llama3.1:8b进入交互界面

spring ai中集成ollama：导入spring-ai-ollama-spring-boot-starter包，添加配置：

spring.ai.ollama.chat.model=llama3.1:8b spring.ai.ollama.base-url= http://localhost:11434

Ollama号称大模型领域的Docker，Docker已推出大模型安装的能力Docker Model Runner。

第五章 一山不容二虎

想要一个工程里共存多个大模型的调用实例，只需构建多个ChatClient，每个ChatClient依赖不同大模型的ChatModel。

源码分析如何同时导入两个ChatClient（OpenAi的和Ollama的），依赖自动装配。 ChatClient.Builder用来创建ChatClient。 观察ChatClientAutoConfiguration类，@ConditionalOnClass(ChatClient.class)只要ChatClient对应的类存在即生效。在该类中定义ChatClient.Builder，核心就是依赖 ChatModel ,当ChatModel存在时则自然创建ChatClient.Builder实例，ConditionalOnMissingBean自己创建ChatClient.Builder就不会自动创建。

总结：ChatClient.builder由自动装配机制申明，本质是DefaultChatClientBuilder，核心依赖ChatModel的注入做实例化。ChatModel也是自动装配的。

解决：手动构建多个ChatClient，分别依赖不同的大模型。在BeanConfig中用@Bean创建。

遇到问题：pom导入ollama的包总是报错。没法手动创建Ollama的ChatClient Bean。

Advisor 机制类似 AOP，可以在调用前后插入逻辑，可以自定义 Advisor 实现日志、缓存、限流等功能。 chatModel.call()最终把请求转发到各个大模型的API调用规范实现上。

第六章 spring ai实现聊天记忆、多用户隔离、持久化存储

在 Spring AOP 中，Advisor 用于将 切点（Pointcut） 和 通知（Advice） 组合在一起，明确告诉 Spring AOP 框架：“在哪些类/方法上应用什么类型的通知”。它是 Spring AOP 实现横切关注点（如日志、事务、安全等）的核心机制。可以通过xml配置实现，也可以通过@AspectJ注解，Spring自动将切面中的通知和切点组合成Advisor，也可以编程式自定义，Advisor advisor = new DefaultPointcutAdvisor(pointcut, advice);。

spring ai中的advisor：SimpleLoggerAdvisor在大模型执行前后打印日志。

MessageChatMemoryAdvisor来提供聊天记忆功能，接收ChatMemory对象，内部Map<String, List>的ConcurrentHashMap实现。其中可以设置会话id避免张冠李戴。可以在ChatClient发起调用时设置MessageChatMemoryAdvisor，还可以在ChatClient构建时设置默认的advisors。

InMemoryChatMemory是内存记忆，应用重启后会发现记忆直接丢失。 如果想要把记忆永久保存下来，可以考虑使用Mysql、Redis等存储。采用Spring集成Docker的方式引入Redis，可以利用Reids的List操作来做一个简易版的记忆能力，获取指定会话的最新 N 条消息。

springai内置了RedisChatMemory，还有JdbcChatMemory、CassandraChatMemory、Neo4jChatMemory。 做记忆压缩，对长篇大论做总结后记忆、对敏感信息做剔除，不记录用户的隐私信息、性能监控关注Redis的内存使用情况。

第七章 spring ai tool calling

大模型的核心架构（如Transformer）依赖自注意力机制分析文本关系，但缺乏与实时数据源的直接交互能力。大模型学习的是海量数据中的统计规律和知识关联。

利用@Tool注解申明将一个方法定义为工具，其中description用来对工具进行描述。 .tools(new DateTimeTools()).call() tools方法中传递可调用的工具清单。

工具可分为两类：信息检索类工具（数据库访问、搜索引擎交互等）、系统操作类（发送电子邮件、修改数据库等）。 也可以使用编程式定义工具，方法不用加注解，ReflectionUtils.findMethod通过反射获取Method，构建ToolDefinition后生成工具的回调类ToolCallback，在大模型调用时传递ToolCallback即可。

前面是Methods as Tools，也可以Functions as Tools，将Function、Supplier等函数式接口定义为工具，首先实现Function接口，然后使用@Configuration和@Bean声明一个Spring Bean，bean名称作为工具名称，@Description作为工具的描述。调用时将bean的名称传递到tools方法中，发起调用。 使用@ToolParam和ToolContext实现工具的输入参数传递。

自定义工具执行可以通过ToolCallingManager工具调用管理器来灵活控制工具执行的生命周期，是一个基于大模型交互的工具管理器。

第八章 spring ai mcp

Anthropic发布模型上下文协议MCP，旨在标准化应用程序向大语言模型（LLM）提供上下文的交互方式。

MCP（Model Context Protocol）就是一种通用标准协议，让不同的AI模型可以同标准、高效地调用各种各样的封装好工具。

MCP提供：即插即用集成库、供应商灵活切换、数据安全最佳实践。

MCP架构：客户端-服务器架构。MCP宿主为AI工具例如IDE，宿主应用可连接多个服务节点。MCP客户端为协议客户端，维护与服务端1:1连接的通信管道。MCP服务器是轻量化服务程序，通过标准化协议暴露特定能力，包括本地数据源和通过API连接的远程服务。既保证了本地数据的安全性（敏感信息不出域），又实现了云端服务的扩展性。

Cline作为集成MCP Client的宿主机，是一个VSCode扩展，可自定义选择LLM进行编程任务。其中有MCP市场，MCP配置文件中，timeout表示超时时间，command表示启动该MCP Server的命令行工具（npx表示用node.js，其他还有python、java），transportType表示客户端与Server的通信方式，stdio表示通过标准输入输出进行通信。

如何通过spring ai开发一个mcp server：支持两类（三种）传输机制，标准输入/输出（STDIO）、服务端主动向客户端发送事件流SSE（Server-Sent Events），其中SSE可以拆分为基于Spring MVC框架实现的SSE和基于Spring WebFlux响应式编程模型实现的 SSE。基于STDIO形式是将MCP Server当做一个本地的子进程，基于SSE可将MCP Server部署在远端。

STDIO的MCP流程：创建工程，依赖model context protocol server，写一个Service，其中方法用@Tool注解，定义ToolCallbackProvider的bean，在application中配置，mvn打jar包，本地Cline中配置使用该MCP，使用标准输入输出传输模式与客户端通信，强制禁用web容器，指定本地构建的jar包。

SSE的MCP流程：SSE是一种基于HTTP的服务器推送技术，允许服务端主动向客户端发送事件流（如实时数据更新）。是服务端到客户端的单向通信，适合单向数据推送场景。可以用SpringMVC实现（底层依赖Servlet线程模型，手动管理ExecutorService），也可以用WebFlux实现（基于Reactive Streams响应式流，使用Reactor的Flux推送事件，基于netty支持高并发）。 自定义mcp client，通过依赖spring-ai-starter-mcp-client来集成客户端能力，例如集成高德地图mcp。 mcp除了支持Server暴露工具Tools能力外，还支持Resources结构化数据供给，可构建静态资源和动态资源。

第九章 spring ai 之 rag

检索增强生成（Retrieval-Augmented Generation, RAG）一种结合外部知识库检索与大模型生成能力的问答技术方案。它通过将用户查询与相关文档向量进行语义匹配，把检索到的内容作为上下文输入给大模型，从而提升生成结果的准确性与丰富性。

rag流程： 1、文档预处理与向量存储 将生产数据加工为文档，并用嵌入模型转换为向量后存入向量数据库，便于后续语义检索。常用模型有 OpenAI text-embedding、BERT、Sentence-BERT 等。 2、用户查询向量化 用户自然语言查询通过同样的嵌入模型转为向量，保持与文档向量空间一致。 3、语义检索相关文档 计算查询向量与库内文档向量的相似度（如余弦相似度），返回最相近的 Top K 文档作为相关结果。 4、生成增强的 LLM 输入 将用户查询和检索到的相关文档合并，并格式化为 LLM 的输入。 5、大模型生成输出 LLM 基于检索到的文档生成回答，减少幻觉，并对输出进行后处理，返回结构化结果给用户。

向量数据库：一种专门用于存储、索引和检索向量数据（Vector Embeddings）的数据库系统，通过高维向量相似度搜索优化，弥补传统关系/非关系型数据库不足。支持海量数据下的近似最近邻搜索（ANN），毫秒级返回关联文档及其元数据的相似结果，核心能力包括：数百至数千维向量处理、原始文本与元数据（如来源、时间）关联、大规模数据下的快速相似匹配。

第十章 spring ai之agent

Agent定义为能够感知环境、决策并执行动作的智能体，包含Brain（大脑）、Perception（感知）、Action（行动）三大模块，工作流程：感知环境→大脑处理→执行动作→反馈循环。

Brain（大脑）：以LLM为核心，负责记忆、知识存储、推理和规划。

Perception（感知）：扩展多模态输入（文本、视觉、听觉等），增强环境感知能力。

Action（行动）：通过工具使用、具身动作（如机器人控制）与环境交互。

agent分两类：

人工流程编排类（Workflow Agent）：通过预定义代码路径协调LLM和工具的系统。

自主规划类（Agent）：LLM动态指导自身流程和工具使用、自主控制任务执行方式的系统。（提示链、路由、并行化）

都是基于通过检索、工具和记忆增强能力的LLM构建的体系。
