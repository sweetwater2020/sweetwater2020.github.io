VibeCoding学习

Posted on 2026-01-23 Edited on 2026-01-25 In 学习 Views:

Vibe Coding：一种全新的编程范式，Andrej提出，开发者用自然语言描述意图，不依赖逐行审查代码，而是通过运行结果是否符合预期来判断是否达到目标，通过迭代式对话，不断调整直到生成可用代码。

AI原生开发，从Claude Code到OpenSpec

最终目的：OpenSpec和spec-kit来开发真实需求。

一、什么是AI原生开发

AI原生开发是什么：AI原生开发工作流可以拆成三根支柱：可执行的规范（Specs）、持久化的上下文、可编排的行动。

1.1 可执行的规范（Specs）【输入，定义做什么】

过去我们习惯把”需求文档”和”代码”当成两回事——文档写给人看，代码才是机器跑的东西。但在AI原生的玩法里，一份好的需求规格说明（Specification，简称Spec），比如spec.md，它本身就应该是一份**”意图代码”**。这就是说这份文档不再是给产品经理或开发者看的那种松散的自然语言描述，而是一份结构化的、AI能精确理解并照着执行的”高级语言”。

它意味着维护软件的重心，从维护那些天天在变的代码，转移到了维护相对稳定的规范上。需求变了，我们先改spec.md，然后让AI重新生成代码。这就是**规范驱动开发（Spec-Driven Development, SDD）**的核心思想。

1.2 持久化的上下文Context【背景，帮助AI理解怎么做】

这就是CLAUDE.md、AGENTS.md这类上下文文件的作用——它们给AI提供了关于项目的”长期记忆”。更妙的是，这种记忆可以分层设计：

企业级记忆：公司层面的安全红线、合规要求，谁都不能违反

项目级记忆：constitution.md里定义的技术选型、架构原则、编码规范

模块级记忆：某个特定模块的API设计、核心业务逻辑

个人级记忆：你自己的代码风格偏好

这种分层设计让AI在不同场景下能拿到合适的背景知识，既保证了一致性，又足够灵活。

1.3 可编排的行动Actions【执行，负责完成它】

AI能干的不只是读文件、写代码。通过自定义指令（Slash Commands）、钩子（Hooks）和MCP服务器，我们可以给它装上各种”外挂”，让它的能力边界几乎无限扩展。

二、AI编程的演进

2.1 AI作为外部知识库，作为一个外部顾问，需要离开开发环境去咨询，例如ChatGPT、Gemini、Claude等，核心价值是信息检索和知识问答。

2.2 AI作为嵌入式副驾驶，包括各类AI插件（如GitHub Copilot Chat），以及像Cursor这样从头开始就围绕AI构建的”AI原生IDE”。这个阶段提供了强大的编码增强能力，但它本质上仍未脱离”辅助开发者”的范畴。AI在这里是一个聪明的助手，但仍然被动、文件级、行动空间受限且环境绑定。

2.3 AI作为原生工作流智能体，以Claude Code为首的命令行AI智能体代表了这一阶段。这类工具可以感知全局、规划行动、与环境交互。它们不再是被动的助手，而是能够主动执行复杂任务的数字”外包”。这正是AI原生开发真正想要达到的状态。

2.4 AI作为自主软件工程师，面向未来，还未实现，比如Claude Code的”Headless模式”（即无需人工授权的”YOLO模式”）。

演进带来的开发者价值的金字塔的倒转：传统开发模式下，顶层是沟通和需求理解，中间层进行设计和架构，底层基石是编码和实现。AI原生开发模式下，底层基石变为意图定义与规范设计，AI完成从清晰指令到代码，开发者需要定义清晰指令。中间层是设计和工作流编排，不光要设计软件架构，还要设计人和AI怎么配合干活。顶层是编码和实现，大量被AI接管。总之，开发者从代码的生产者变为规范设计者，从任务执行者变为AI工作流的指挥家。

三、SDD的本质，代码为王到规范为王

3.1 之前软件开发的难题：意图和实现之间的鸿沟，PRD产品需求文档到设计文档到代码，文档只是参考，代码才是真相。

3.2 SDD的核心主张：让规范成为真相，让代码变为规范的衍生物。就像源代码编译为二进制文件一样，规范编译为代码。前提是规范必须足够精确，精确到AI能直接照着执行。

3.3 AI扮演的角色：智能编译器，接收人类给出的高层级、非结构化的意图描述Spec，一步步把它转化、细化，最终输出可执行的代码。

3.4 SDD的四个阶段：

第一步：意图定义，只关心业务层面的事情，不关心任何技术细节，包括用什么框架，数据怎么存，接口怎么设计。产出一份清晰的意图描述spec.md。

第二步：技术规划，AI拿到意图定义结合项目的技术栈和架构原则，生成技术实现方案，产出架构设计、数据模型、接口规范等。

第三步：任务分解，把技术方案拆成一个个具体的原子级的开发任务，理清任务之间的依赖关系和可并行点。

第四步：自动化实现，建文件、写代码、跑测试。

总结：传统开发围着代码转，SDD围着规范转，但是，现阶段AI在长链路推理上不够稳定，会失忆、会跑偏。

四、Claude Code实战

为什么用命令行Agent：执行深度和集成自由度。Cursor、Copilot这些IDE内置的AI的执行环境是受限的——只能在IDE能触达的范围内干活，无法跑shell命令等。而命令行Agent可以遍历整个文件系统、执行任意Shell命令、跟任何外部系统交互。更关键的是，它可以被部署到任何地方——服务器、CI流水线、Docker容器——独立运行。IDE插件是”嵌入式助手”，命令行Agent是”可以派到任何地方干活的数字员工”

有哪些Coding Agent：OpenAI的Codex CLI、Google的Gemini CLI、Anthropic的Claude Code（具有先发优势，Sub-agent、Hooks、Checkpointing这些高级能力目前基本只有它有）。

Claude Code：quick start https://code.claude.com/docs/en/quickstart?spm=ata.21736010.0.0.436075368q60Dg（下达指令后会自己拆解任务，实时展示执行过程，有自动记忆压缩，支持MCP服务添加）

4.1 Claude Code分层配置体系

Claude Code的配置不是一个文件搞定的，而是一套分层结构，高层级配置会覆盖低层级的同名设置：

企业级策略（managed-settings.json）：IT部门统一下发，优先级最高，不可覆盖

命令行参数（–model等）：单次会话的临时覆盖

项目级个人配置（.claude/settings.local.json）：你在这个项目的个人偏好，不提交Git

项目级团队配置（.claude/settings.json）：团队共用，要提交Git

用户级全局配置（~/.claude/settings.json）：你个人的全局偏好

4.2 Claude Code核心交互

@是”喂上下文”：引用单个文件：@/src/main/java/SomeClass.java、引用整个目录：@/src/

!是”执行命令”：语法：! <shell命令>，跑个Git命令：! git log –oneline -5、编译项目：! mvn compile

4.3 长期记忆CLAUDE.md与AGENTS.md

@指令给的是”这次对话需要看的内容”，属于短期记忆。但有些信息是每次对话都需要的——项目的技术栈、团队的编码规范、常用的命令……这些内容应该写进CLAUDE.md。它会在每次启动会话时自动加载，成为AI的”长期记忆”。

AGENTS.md是另一类上下文文件。它是OpenAI、Google等公司和社区一起推的开放标准（agents.md），目标是建立一个”AI Agent通用的项目说明书”格式。包含：项目概述、常用命令、项目结构。

实践中使用：AGENTS.md放通用信息，任何Agent都能理解的部分。CLAUDE.md放Claude Code专属的配置。在CLAUDE.md中导入通用规范@AGENTS.md。都要git到代码库，/memory查看会话上下文。

4.4 项目宪法constitution.md

这个概念来自spec-kit。如果说CLAUDE.md是”操作手册”，constitution.md就是”根本大法”，是原则是红线。

4.5 工具箱Slash Command

斜杠命令可以把那些高频、复杂的工作流封装成一个简单的指令，一键调用。有一些官方的内置命令，可以/help查看。可以自定义命令存在commands文件下，团队共享和用户级。

五、OpenSpec和Spec-kit两个SDD工具

5.1 OpenSpec：fission-ai开源的SDD框架和命令行工具，轻量灵活

主打“小步快跑”，特别适合在老项目上加功能、改逻辑；

用 changes/ （存放正在进行的变更提案）和 specs/ （存放已经实现并验收的功能规范）两个文件夹管变更，一目了然谁在开发什么；

规范写得简洁（约250行），review轻松，不强迫你立“宪法”，靠自觉+好习惯；

流程（三步骤）：/openspec:proposal：创建变更提案、/openspec:apply：应用变更实现、/openspec:archive：归档完成的变更。归档后可以用openspec view查看dashboard，一种delta格式描述变更，天然适合”我要在现有系统上加个功能”这种需求。

安装简单（npm一条命令）上手零压力。

5.2 Spec-kit：GitHub出品的SDD工具，严谨，规范完整

核心理念是规范即代码Specification as Code，强调从原则到实现的完整链路，每一步都有明确的产物和校验机制，引入Constitution宪法，不可妥协的原则。

适合从零开始的新项目，或需要强流程的大团队；

流程（五步骤）：/speckit.constitution → 建立项目原则、/speckit.specify → 描述要做什么（纯功能层面）、/speckit.plan → 技术方案设计、/speckit.tasks → 任务分解、/speckit.implement → 执行实现

输出非常详细（800+行），每一步都留痕，还能自动检查是否守规矩（比如没写测试就卡住）；

依赖Python和uv，环境配置稍麻烦，但换来的是结构清晰、角色分明。

5.3 OpenSpec和Spec-kit的区别：1、规范产出量不同；2、流程复杂度，OpenSpec三步，规划-开发-交付，Sepc-kit五步+校验，规划-开发-测试-审查-交付-校验；3、宪法约束不同，一个是可选自觉，一个是强制门控；4、变更管理不同，一个是目录结构，一个是Git分支；

六、关于SDD思考

6.1 SDD的实践层次：

Spec-first（规范先行）：先写规范，再辅助开发（当前主流状态）

Spec-anchored（规范锚定）：规范持续留存，指导后续演进与维护（较少实现）

Spec-as-source（规范即源码）：规范是唯一权威源文件，代码完全由其生成，人类永不直接修改代码（理想但尚未成熟）

6.2 关于SDD的质疑：1、普适性困境：标准化工作流（如spec-kit）难以适配所有问题规模；2、审查成本：大量生成Markdown规范文件，审查难度超过审查代码；3、控制幻觉：AI的上下文理解偏差和推理不稳定而偏离指令；4、规范边界模糊：功能规范和技术规范在实践中何时该抽象何时该具体的失焦。

6.3 SDD和MDD模型驱动开发：都是以高层抽象（UML/自然语言Spec）作为真理之源生成代码，但是LLM无需构建复杂解析器，但是引入非确定性。

6.4 怎么实践：构建项目专属的AI资产，Agent.md、CLAUDE.md、constitution.md；渐进式采用SDD工作流；AI原生开发不是简单的用AI写代码，而是开发范式的根本转变，代码和规范哪个才是真理之源，核心价值是编写代码还是定义意图。

AI Coding和Claude Code

一、AI Coding经验

Prompt 质量 = 输出质量上限，推崇 COSTAR 框架构建清晰指令。在 Claude 中善用伪 XML 标签提升模型理解精度。

上下文工程：主动管理 AI的“工作记忆”，进行信息压缩，为了避免上下文丢失的情况，将关键信息提取成markdown 放到 memory bank。

对于已有项目，先给Al提供更多信息，像Claude Code，提供了/init 指令，目的是为了让AI快速了解项目的背景、技术架构等，知识库记录了业务需求、技术规约、常见的工程流程等信息。

二、如何使用Claude Code

Claude Code 官方文档: https://code.claude.com/docs/zh-CN/overview#claude-code-%E4%B8%BA%E6%82%A8%E5%81%9A%E

Claude Code Router：被设计为 Anthropic官方命令行工具 Claude Code的一个强大扩展。它允许将用户的代码生成请求，路由到不同的大模型平台以及指定的模型。专为模型路由设计。它支持将代码生成请求智能分发至多个大模型平台（如 DeepSeek、Gemini、 Ollama、OpenRouter 等），并可基于任务类型（如 think、longContext、webSearch）、上下文长度或推理模式自动选择最优模型，实现多供应商整合与动态负载分发，显著超越 Claude Code 原生的手动模型配置能力。

推荐使用模型：Qwen3-Coder-480B-A35B-Instruct、GLM-4.7、Kimi-K2-Instruct-0905。能生成代码，能写文件，能用Skills。

1.安装

安装NodeJS：版本要>=18，Node.js 是让 JavaScript 能在浏览器外运行的环境，可用来写服务器、工具和脚本。安装 claude-code 需要NodeJS，因为它本质是一个基于 Node生态的命令行工具，通过 npm 安装和运行。

npm是Node.js 的包管理器，用来安装、更新和管理各种JavaScript 库与工具。全球大量开源项目都通过 npm分发，因此它也是 Node生态的核心。开发者使用npm 可以方便地安装依赖、运行脚本、发布自己的工具，是Node.js 项目运作的基础。

nvm 是 Node.js 的版本管理工具，用来在同一台电脑上安装、切换和管理多个不同版本的Node.js。它解决了项目对 Node 版本要求不一致的问题，让开发者可以快速切换环境，避免兼容性冲突。

交装claude： 安装命令：npm install -g @anthropic-ai/claude-code。

2.Claude Code使用

ClaudeCode 的交互主要通过斜杠/命令、@文件引用、＃记忆符号来完成。

项目级记忆：在项目根目录的./CLAUDE.md文件中定义，团队共享。内容可以是项目架构、编码规范等。

用户级记忆：在~/.claude/CLAUDE.md 文件中定义，属于个人偏好。内容可以是代码风格、常用工具等。

临时添加记忆：在对话中使用＃符号。

示例：# 我是一名 Java 后端开发者，请使用 Spring Boot 风格回答问题

执行终端命令用！，例如!ls -i。

还可以创建自己的快捷命令来简化重复性输入。

IDE集成

/init指令，可以让Claude Code扫描整个工程，了解项目结构，并将结果写入CLAUDE.md文件。

可以通过/memory 直接编辑这个文件，也可以用#命令追加内容。

建议在CLAUDE.md中包含以下关键内容：

  1. AI必须了解的核心信息：项目背景、技术栈、架构设计等
  2. 项目编码标准、流程等指导AI正确执行任务的行为准则

对于常用框架、开发语言规范甚至是工作流，可参考GitHub上的优质资源，如awesome-cursor-rules-mdc，描述了各种语言、各种框架沉淀的code conduct。

如果单个CLAUDE.md信息量过大，可以将其分层分模块存储，按模块准备不同的CLAUDE.md文件。Claude会从修改最深一级的记忆开始查找。
