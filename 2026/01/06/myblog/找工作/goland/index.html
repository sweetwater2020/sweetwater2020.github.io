Go 语言简介

Go（又称 Golang）是由 Google 于 2009 年推出的开源编程语言，由 Robert Griesemer、Rob Pike 和 Ken Thompson 设计。其设计目标是简洁、高效、并发友好、易于部署。Go 语法接近 C 语言，但去除了复杂的特性（如继承、泛型早期版本缺失等），内置垃圾回收（GC）、并发原语（goroutine 和 channel），编译速度快，生成静态链接的二进制文件，非常适合构建高性能、高并发的网络服务和云原生应用。

Go 与 Java 的主要区别

维度 Go Java
语言范式 过程式为主，支持简单面向对象（无类、无继承） 纯面向对象（一切皆对象，支持继承、多态）
并发模型 基于 CSP 模型，使用 goroutine + channel，轻量高效 基于线程 + 锁（如 synchronized、ReentrantLock），重量级
运行方式 编译为本地机器码，直接运行二进制 编译为字节码，在 JVM 上运行
内存管理 自动 GC，但更注重低延迟（STW 极短） 自动 GC，JVM 提供多种 GC 算法（如 G1、ZGC）
部署 单一静态二进制文件，无需依赖环境 需安装 JRE/JDK，依赖 classpath 和 jar 包
错误处理 显式返回 error 值，强调“错误是值” 使用 try-catch 异常机制
泛型支持 Go 1.18（2022）起支持泛型 Java 5（2004）起支持泛型
构建速度 极快，适合大型项目快速迭代 相对较慢，尤其大型项目编译耗时
生态与场景 云原生、微服务、CLI 工具、基础设施（如 Docker、K8s） 企业级应用、Android 开发、大数据、传统后端系统

总结

  • Go 更适合：追求开发效率、部署简单、高并发、低延迟的现代云服务。
  • Java 更适合：复杂业务逻辑、强类型安全、成熟企业生态、长期维护的大型系统。

两者并非替代关系，而是适用于不同场景。许多公司甚至在架构中同时使用 Go（做网关/中间件）和 Java（做核心业务）。

Go 是编译型语言。

具体来说，Go 源代码（.go 文件）通过 Go 编译器（如 go build）被直接编译成目标平台的机器码，生成一个独立的、静态链接的可执行二进制文件。这个文件不依赖 Go 运行时环境或虚拟机，可以直接在相同操作系统和架构的机器上运行。

这与解释型语言（如 Python、JavaScript）不同——后者通常需要解释器逐行读取并执行源代码；也不同于 Java 这类“半编译”语言（编译为字节码，再由 JVM 解释或 JIT 编译执行）。

✅ Go 的编译特点包括：

  • 编译速度快；
  • 生成单一可执行文件，部署简单；

1. Go 的协程（Goroutine）是什么？
Goroutine 是 Go 语言提供的轻量级并发执行单元，由 Go 运行时调度，而非操作系统线程。启动成本低（初始栈仅 2KB），可同时运行成千上万个，通过 channel 安全通信，是 Go 高并发模型的核心。

2. defer 的作用和执行顺序？
defer 用于延迟执行函数调用，常用于资源释放（如关闭文件）。多个 defer 按“后进先出”（LIFO）顺序执行，在函数 return 前、panic 后仍会执行，确保清理逻辑可靠。

3. Go 中如何实现面向接口编程？
Go 采用隐式接口实现：只要类型实现了接口的所有方法，就自动满足该接口，无需显式声明（如 Java 的 implements）。这提高了代码灵活性，便于解耦和测试。

4. slice 和 array 有什么区别？
Array 是固定长度的值类型，赋值会复制全部元素；slice 是动态长度的引用类型，包含指向底层数组的指针、长度和容量。slice 更常用，支持 append 等操作。

5. map 是线程安全的吗？如何安全使用？
map 不是并发安全的，多个 Goroutine 同时读写会导致 panic。应使用 sync.RWMutex 保护，或在读多写少场景下使用 sync.Map，避免数据竞争。

6. channel 的用途和注意事项？
channel 用于 Goroutine 间通信和同步。nil channel 读写会永久阻塞；向已关闭 channel 发送数据会 panic；应由发送方关闭 channel，接收方可通过 ok-idiom 判断是否关闭。

7. Go 的内存逃逸是什么？如何查看？
当局部变量在函数返回后仍被引用，编译器会将其分配到堆上（逃逸）。可通过 go build -gcflags="-m" 查看逃逸分析结果，有助于优化性能和减少 GC 压力。

8. context 包的作用是什么？
context 用于传递请求生命周期内的取消信号、超时和上下文数据。常用于 HTTP 服务、数据库调用等，实现跨 Goroutine 的优雅取消与超时控制，避免资源泄漏。

9. Go 中如何处理错误？
Go 采用显式错误返回机制，函数通常返回 (value, error)。调用者必须显式检查 error，不依赖异常。panic/recover 仅用于不可恢复的严重错误，不用于常规流程控制。

10. init 函数的执行时机和用途？
init 函数在包被导入时自动执行，早于 main 函数。用于初始化全局变量、注册驱动或设置配置。同一包内多个 init 按文件名和定义顺序执行，每个文件可有多个 init。

11. Go 的垃圾回收（GC）机制是怎样的？
Go 使用并发、三色标记清除算法的 GC，从 1.5 版本起实现低延迟（STW 时间通常 < 100 微秒）。GC 自动管理堆内存，开发者无需手动释放。可通过 GOGC 环境变量调整触发频率。

12. 什么是 sync.WaitGroup？如何使用？
sync.WaitGroup 用于等待一组 Goroutine 执行完毕。主 Goroutine 调用 Add(n) 增加计数，每个子 Goroutine 完成后调用 Done()，主 Goroutine 通过 Wait() 阻塞直到计数归零。

13. Go 中的 nil 是什么？哪些类型可以为 nil？
nil 是 Go 中指针、切片、map、channel、函数、接口等类型的零值，表示“未初始化”或“空”。注意：数组、结构体、基本类型（如 int、bool）不能为 nil。

14. make 和 new 的区别是什么？
new(T) 分配类型 T 的零值内存并返回 *T；make 仅用于 slice、map、channel，不仅分配内存还完成初始化（如设置长度、容量），返回的是 T 而非指针。

15. Go 中如何避免 Goroutine 泄漏？
Goroutine 泄漏常因未正确退出导致。应使用 context 控制生命周期、确保 channel 通信有接收方、避免无限循环无退出条件。监控工具（如 pprof）可辅助检测。

16. 说说 Go 的调度模型（GMP 模型）？
Go 采用 GMP 调度模型：G（Goroutine）、M（系统线程）、P（逻辑处理器）。P 维护本地 Goroutine 队列，M 绑定 P 执行 G。该模型实现高效并发与负载均衡。

17. 互斥锁（Mutex）和读写锁（RWMutex）的区别？
sync.Mutex 同一时间只允许一个 Goroutine 访问临界区；sync.RWMutex 允许多个读操作并发，但写操作独占。适用于读多写少场景以提升并发性能。

18. Go 中字符串（string）可以修改吗？为什么？
不可以。Go 的 string 是只读的字节序列，底层为不可变数组。若需修改，应转为 []byte 处理后再转回 string，但会引发内存拷贝，需注意性能开销。

19. 什么是空 struct{}？有什么用途？
struct{} 是零大小的结构体，不占用内存。常用于 channel 通信中仅传递信号（如 chan struct{}），或作为 map 的值实现集合（set）功能，节省内存。

20. Go 支持泛型吗？如何使用？
从 Go 1.18 起支持泛型。通过类型参数（如 func Print[T any](v T)）编写通用函数或类型。泛型提升代码复用性，同时保持编译时类型安全，避免 interface{} 的类型断言开销。
